# netvtk-core

SWIG-generated C# bindings for VTK 9.7.1: one C# namespace, `Vtk`, VTK's class and method names unchanged; one SWIG module per VTK module (`<Module>Module`, internal). Monorepo rules: `../CLAUDE.md`; open work: `../plan/`.

The modules in `src/SWIG_files/wrapper` (25 VTK modules, and RenderingOpenGL2Win32: RenderingOpenGL2's Windows-only headers), their `headers/`, `modules.json`, `platforms.json`, `classes.json` and the structs in `src/NetVtk/<Module>/*.g.cs` are written by `../netvtk-generator` (banner `generated by netvtk-gen from VTK <version>`): change the generator or its config, never the files. Hand-written: `src/SWIG_files/common/*.i` (the typemap library), `src/SWIG_files/extras/<Module>.i` (companions), `src/Native/` (NetVtkRuntime), `src/NetVtk/Runtime/`.

## Commands

```bash
python build.py tools                        # once: SWIG 4.5.1 from conda-forge into .tools/ (micromamba)
python build.py vtk --triplet x64-windows    # VTK via vcpkg: about 23 min first time (x64 and x86 alike); cached after
python build.py generate                     # after any .i change
python build.py native --triplet x64-windows # after generate; repeat for x86-windows
python build.py test --arch x64              # every framework, net35 on CLR 2; also --arch x86; --no-rendering without OpenGL 3.2
python build.py docs --triplet x64-windows   # VTK's doc comments -> artifacts/docs/NetVtk.xml (needs ../netvtk-generator)
python build.py pack --rids win-x64,win-x86  # NuGet into artifacts/packages (CI packs all four RIDs)
python build.py test-package --arch x64      # the packed NetVtk as an app consumes it
python test/test_build.py                    # build.py's version, changelog, SWIG message and library folder rules
python build.py registry                     # versions/ at the repository root after a committed port change (--check: CI)
# the hand-written C++ against .clang-format, with CI's clang-format (a venv under .tools/)
python -m venv .tools/clang-format && .tools/clang-format/Scripts/python -m pip install clang-format==20.1.8
.tools/clang-format/Scripts/clang-format --dry-run --Werror src/Native/*.cxx src/Native/*.hxx
```

Logs into `log/` (gitignored): `python build.py test --arch x64 > log/test-x64.log 2>&1`. Linux: `docker/linux-x64.Dockerfile` (header comment), with Docker Desktop running.

## VTK (the vcpkg port)

- **`vcpkg/ports/vtk`** builds VTK 9.7.1 from Kitware's GitHub tag with NetVtk's module set (`../netvtk-documentation/articles/modules.md`; `NETVTK_MODULES`, every group `DONT_WANT`; VTK enables what they depend on: 77 libraries). Features add modules: `volume` (RenderingVolume, RenderingVolumeOpenGL2), `exodus` (IOExodus), `cgns` (IOCGNSReader); `vcpkg.json` asks for all of them; a project that builds VTK from this registry asks for the same, or builds another VTK. Its third-party libraries are VTK's own copies with mangled symbols: the port depends on no other port, and nothing clashes with the zlib or FreeType other libraries in the process link. 64-bit ids on every architecture (`VTK_USE_64BIT_IDS`), `STDThread` SMP, no wrapping, versioned names (`vtkCommonCore-9.7.dll`). The port writes `vtkNetVtkBuild.h` into VTK's headers (`NETVTK_VTK_BUILD`, `9.7.1#<port-version>`), which `Vtk.VtkBuild` reports. win-x86 builds at `/O2 /Os` (`vcpkg/triplets/x86-windows.cmake`): MSVC's x86 `/O2` alone miscompiled `vtkActor::GetBounds`.
- **Patches** (`PATCHES` in the portfile, `git format-patch` files, applied in order), two on `vtkWin32OpenGLDXRenderWindow` (`Win32RenderWindowTests`), one on `vtkOpenGLHardwareSelector` (`HardwareSelectorTests` too), two on the depth (`ReverseZTests`, `ReverseZFeatureTests`):
  - `0001-dx-render-window-makes-its-context-current.patch`: the window makes its own OpenGL context current before its interop calls (`Lock`, `Unlock`, `RegisterSharedTexture`, `UnregisterSharedTexture`; `SetSize` goes through the last two). Unpatched, it used whichever was current: a window resized after another rendered registered its texture name in the other's context. Without an interop device (no `WGL_NV_DX_interop`, or no Direct3D device) `RegisterSharedTexture` reports an error and registers nothing, where it called the missing extension and crashed.
  - `0002-dx-render-window-closes-its-interop-device.patch`: its destructor unregisters the shared textures and closes the interop device (`wglDXCloseDeviceNV`) while its context lives. Unpatched, nothing closed it: the device it held stayed alive after the window, with every texture made on it.
  - `0003-hardware-selector-keeps-the-render-framebuffer.patch`: the selector's passes render into the window's resolve framebuffer (one sample, the window's size and formats), swapped in for a multisampled render framebuffer while they render (`vtkOpenGLRenderWindow` declares the selector a friend). Unpatched, it set the window's samples to 0 and back, and the window re-created its render framebuffer before the passes and after them: a DX window's shared texture was no longer the one it rendered into (its frames froze at the first pick), and every capture cost time and memory. Disabling `GL_MULTISAMPLE` instead keeps the framebuffer but blends ids where surfaces cross: NVIDIA's driver tests depth per sample with multisampling disabled.
  - `0004-render-window-reverse-z.patch`: `vtkRenderWindow::UseReverseZ`, depth from 1 at the near plane to 0 at the far one in 32-bit floats, which resolves about the same share of any distance whatever the clipping range's ratio. An OpenGL window makes its render, display and resolve framebuffers with float depth (`PopulateFramebuffer`'s `floatDepth`; their blits need one format), clips depth to [0, 1] (`glClipControl`; without OpenGL 4.5 or ARB_clip_control it turns it off and warns), tests `GL_GEQUAL` and clears depth to 0; `vtkOpenGLCamera`'s matrices and `vtkRenderer`'s view and display conversions follow, so a depth read from the window goes back to its world point; coincident-topology offsets turn round, a constant unit 1/65000 of the fragment's own depth.
  - `0005-reverse-z-where-depth-is-handled.patch`: what computes, compares or converts depth itself follows `UseReverseZ`, read when it renders (a uniform, or a bit of the polydata mapper's shader-change value): impostor spheres and tubes, the sphere and stick mappers, 2-D actors (they sat at NDC z -1, which the [0, 1] clip range drops) and labels, depth peeling, dual depth peeling, OIT, SSAO, EDL, depth of field, point fill, the shadow baker, the skybox, pickers and widgets, the volume mappers. No member added. Passes built on conventional formulas take `1 - depth`: right, at conventional precision.
- VTK's two executables go to `tools/vtk`, where the config fixup points its CMake targets. Its licenses (its own, its modules', the third-party ones) go to `share/vtk/licenses/VTK`, from which `build.py native` writes `THIRD-PARTY-NOTICES.txt`.
- The `opengl` feature is empty (OpenGL is always built), for consumers that ask for `vtk[opengl]`.
- **Triplets:** release-only, macOS deployment target 14.0. vcpkg's ABI hash covers the triplet file: a project that builds VTK from this registry with copies of `vcpkg/triplets` (and the same features) gets NetVtk's build, with the same ABI hash, and either binary cache serves the other. A change here is a change for such copies too.

## Wrapper contract

- **VTK objects** (`common/VtkObjects.i`): `%vtk_object(T)` before each class deriving from `vtkObjectBase`. The proxy is the object and owns one reference; Dispose and the finalizer drop it (`UnRegister`: SWIG's unref feature, no ref feature).
  - `T::New()` and `NewInstance()` hand over a reference of their own: declared `T*`. Every other returned object gets one from the wrapper: declared `T* const`. A callback's object parameter too.
  - `%vtk_new(T)`: a C# constructor calling `T::New()`; the object factory picks the class (`new vtkRenderWindow()` is the platform's OpenGL window).
  - The finalizer may delete an object on its own thread. Rendering objects release OpenGL resources in their destructors: dispose them on the rendering thread.
- **Size hints:** a pointer VTK returns with `VTK_SIZEHINT(N)` is a C# array of N, copied right after the call: `%apply TYPE *NETVTK_SIZE<N> { TYPE *Member }` before the declaration, `%clear` after (`%netvtk_sized_return`; double and int, N = 2, 3, 4, 6). A `T*&` parameter of numbers a hint names (`VTK_SIZEHINT(pts, npts)`) is a `ref T[]` of as many elements as the count holds after the call, copied right after it: netvtk-gen declares the parameter as written, `%netvtk_sized_ref(T, name, CSTYPE, SIZE)` before (SIZE in the wrapper's terms: `(*arg3)` for a reference argument, `result`), `%clear` after; the argout writes the pointer and the count into the `long[2]` C# passes.
- **Value classes' data:** their public fields are C# properties (netvtk-gen), each typemap file with its `csvarout`: numbers, enums, strings, structs and value classes (copies: ValueTypes.i) read and written; C arrays (Types.i) and `std::array`s, C# arrays of their length; vectors (Std.i), a const one and one of VTK objects by pointer read only; VTK objects read only (`T* const`: VtkObjects.i's `csvarout` gives the proxy a reference of its own), `vtkSmartPointer`s read and written; C strings read only (`const char* const`); pointers to other classes read only, borrowing proxies (`T* const`, References.i); `void*` an `IntPtr`, any other pointer one read only (`void* const`). NetVtk.i's `%naturalvar` makes a class-typed field's getter a const&, not a pointer into the object (Std.i declares `std::vector` and `std::array` for it); SWIG writes no csin `pre`/`post` in setters. Types.i has the property getters of the numbers whose C# types it changes (C `long`, `size_t`, `char16_t`, the width typedefs), Strings.i the strings'. `vtkHardwareSelector_PixelInformation` (`Valid`, `Prop`, `AttributeID`) reads a pixel after `CaptureBuffers()`, on a window rendered once; `vtkRenderTimerLog_Frame.Events` (each event's `Name`, `ElapsedTimeMilliseconds()`, nested `Events`) times a render on the GPU (`GetRenderTimer()`, `SetLoggingEnabled(true)`, renders until `FrameReady()`, `PopFirstReadyFrame()`).
- **Width typedefs:** `vtkIdType` and `vtkMTimeType` keep their names in the wrappers (`long long` or `long` per platform): C# `long` and `ulong`. C `unsigned long` (event ids, observer tags) is `ulong`, range-checked on Windows (`Types.i`).
- **Directors** (`common/Directors.i`): `%netvtk_director(T)` turns on SWIG's director for a class C# subclasses (`directors` in netvtk-gen's config; the module is `%module(directors="1", dirprot="1")`), `%netvtk_directed(T)` keeps a proxy's identity for its bases. An exception an override throws does not unwind through VTK: `Directors.Fail` parks it and hands its number to NetVtkRuntime (`NetVtk_DirectorFailed`); the callback returns (an override with a result returns its default) and VTK goes on; the wrapped call that led to it takes the number after its call (`Exceptions.i`) and C# throws a `VtkException` (`NetVtk_ManagedException`) whose InnerException is the C# one. NetVtkRuntime holds it per thread for every wrapper library: the callback's module and the call's differ.
- **Exceptions:** `VtkException` carries a C++ exception's type (`std::bad_alloc`, `std::out_of_range`, ...) and message. VTK reports its own errors through `vtkOutputWindow`, not exceptions.
- **Proxy constructors** `(IntPtr, bool)` are `protected internal`: another binding's proxies derive from NetVtk's in its own assembly (`NetVtkInterop.i`). Other code makes proxies with `vtkObjectBase.FromNativePointer<T>(pointer, ownsReference)` (a reference of its own, checked by `T.SafeDownCast`); `NativePointer` is the object's `vtkObjectBase*`.
- **Hand-written members:** every proxy is `partial` (`NetVtk.i`); `src/NetVtk/<Module>/<Class>.cs` adds C#: `vtkObjectBase` (`ToString` from VTK's `Print`, native pointers), `vtkObject` (handlers as observers: `AddObserver(id, handler)`, `Observe`, the events `ModifiedEvent`, `ErrorEvent`, `WarningEvent`), `vtkAlgorithm` (`StartEvent`, `ProgressEvent`, `EndEvent`), `vtkDataArray` (`ToDoubleArray`: a typed loop through `vtkArrayDispatch` for VTK's AOS and SOA arrays, value by value for the others). The typed arrays' bulk members are `cscode` macros in `extras/CommonCore.i` (`ToArray`, `CopyFrom`, `AsSpan` on .NET 6+, `FromArray`), copying with NetVtkRuntime's `NetVtk_CopyMemory`.
- **NetVtk's own director subclasses** (`DelegateCommand`, `VtkOutput`'s output window) carry `[CSharpOverrides]`: `Directors.Overrides` connects no callbacks for the other types of NetVtk's assembly, its proxies, whose overrides are C++'s.
- **Messages:** `VtkOutput.Install()` (or a `Message` handler) makes a C# `vtkOutputWindow` subclass VTK's instance: every message to `Message`, to `Trace` without a handler. The tests install it (`TestSetUp`): VTK's own opens a window on Windows.
- **Finalizer:** `VtkFinalizer.Context` set, the finalizer posts the release there (`csdispose` of `vtkObjectBase` in `VtkObjects.i`).
- **Package:** NetVtk carries the SWIG files it was built from in `swig/` (`common`, `wrapper`, `extras`, `headers`, the JSON indexes) and `swig/interop/NetVtkInterop.i`.
- **IntelliSense:** `build.py docs` runs `netvtk-gen docs` over VTK's installed headers and the net10.0 assembly: VTK's doc comments as `artifacts/docs/NetVtk.xml` (about 1,950 of 2,450 types and 48,000 of 61,000 members), merged with the compiler's file for the hand-written members. `pack` puts it in place of the compiler's file in every framework, with `VTK-LICENSE.txt` beside it, and the license expression becomes `MIT AND BSD-3-Clause`; without it, pack warns. VTK's text: never committed.
- **Interop for other bindings** (`src/SWIG_files/interop/NetVtkInterop.i`): another SWIG binding `%include`s it, not NetVtk's typemap library, whose typemaps use NetVtk's internals and whose global ones would apply to the binding's own classes. `%netvtk_object(T)` passes NetVtk's objects (`NativePointer` in, `FromNativePointer` out, with NetVtk's reference rules); `%netvtk_derived(T, Base)` makes the binding's VTK class a subclass of NetVtk's proxy (the `protected internal` pointer constructor; the base proxy holds and drops the reference); `%netvtk_build(NAME)` compiles in the port's `vtkNetVtkBuild.h` (`NETVTK_VTK_BUILD`, VTK's version and the port-version), which the binding passes to `Vtk.VtkBuild.Require` at load. Change it as public API: bindings build on it. **A port change that alters VTK's headers or ABI raises the port-version** (the registry check enforces it for any port change), so bindings built on the old one fail at load.
- **Autoinit:** a library registers the object factories that override the classes its classes make when it loads (`VTK_MODULE_INIT` in a companion's `%{ %}`), as VTK's autoinit does for an application: .NET loads each NetVtk library at its first call, and whichever class a process makes first must find them registered (`ObjectFactoryTests`, each case in a process of its own: the test assembly is an app on .NET, `FirstObject`). RenderingCore's companion defines `%netvtk_rendering_factories` (RenderingOpenGL2, InteractionStyle, RenderingFreeType, RenderingUI) and invokes it; RenderingOpenGL2Win32's and InteractionStyle's invoke it too, once per library (NetVtkWin32: a window's render timer; NetVtkInteraction: a style's or widget representation's actors, mappers and properties). A macro, not a shared file: SWIG includes a file once per module, and the modules import RenderingCore's first. RenderingVolume registers RenderingVolumeOpenGL2.
- **Native libraries:** `NetVtk<Group>` per entry of `src/SWIG_files/modules.json` (Common, Filters, IO, Rendering, Interaction, Win32), each linking all of VTK (exports, of 65535, win-x64 2026-10-17: Common 30,602, Rendering 12,388, Filters 10,919, Interaction 7,051, IO 2,785, Win32 92); `NetVtkRuntime` (director failures, memory streams) links nothing and every wrapper library links it. A library of `platforms.json` holds one platform's classes (Win32: `win`): `build.py generate` puts its C++ in `build/generated/cxx/<os>/`, which CMake builds there only, so only that platform's runtime packages hold it; its C# is in NetVtk.dll, and elsewhere its first call throws a TypeInitializationException around a DllNotFoundException.
- **The rest of the typemap library:** `Types.i` (numbers by value and by `ref`, never `out`; pointers to numbers as C# arrays; addresses), `References.i` (a member's `T&` return: a C# `ref` for numbers, enums and structs, a borrowing proxy for classes; `NativeKeep` keeps an argument a class refers to alive with its proxy), `Strings.i` (UTF-8 both ways, by hand: netstandard2.0 has no `LPUTF8Str`), `Streams.i` (`std::ostream&`/`std::istream&` as a C# `Stream` lent for the call, through native memory streams), `ValueTypes.i` (blittable structs, returned through a thread-local buffer), `Std.i` (the standard library types signatures and value classes' fields use; `std::vector` as C# arrays both ways: C# passes a byte block, the elements' count, a cell for what comes back and the elements, and reads what comes back as a thread-local count and address, `NativeArrays`; a macro per element type, VTK objects' `%netvtk_object_vector` in VtkObjects.i). `NativeLibraryLoader` loads the `NetVtk*` libraries before the first P/Invoke, from `<arch>/` (the AnyCPU .NET Framework layout), `runtimes/<rid>/native/` or the directory itself, relative to the app and then to NetVtk.dll; VTK's libraries come along through the OS loader.

## Registry and CI

- **vcpkg registry:** the repository is a vcpkg git registry for the VTK port: `versions/` (repository root) names each port version's git tree. After a change to `vcpkg/ports/vtk`, commit it, raise its `port-version` if its version stays, run `python build.py registry` and commit `versions/`; `build.yml` fails on a stale one (`registry --check`). Consumers pin the registry at a NetVtk release's commit: never rewrite published history.
- **Rendering tests** (`[Category("Rendering")]`) need OpenGL 3.2: CI runs them on Linux (Xvfb, Mesa's llvmpipe) and leaves them out on Windows and macOS (`--no-rendering`). The Direct3D ones (`[Platform("Win")]`) run on a Windows machine with a GPU only.

## Rules

- **License:** MIT only. No VTK doc text in committed files. VTK's sources and wrapping tools (BSD-3) may guide rules; ActiViz and other bindings' code never.
- **C#:**
  - Modern language features: file-scoped namespaces, switch and collection expressions, primary constructors.
  - The lowest target is net35 (CLR 2): library code uses compiler-only features and .NET 3.5 APIs, or `#if NETFRAMEWORK`/`NET5_0_OR_GREATER`. No tuple syntax (`System.ValueTuple` comes with 4.7), no `RuntimeInformation`, `AppContext`, `Environment.Is64BitProcess` or `Path.Combine` with more than two parts.
  - Never implicit usings. Using groups, blank-line separated, IDE order within each: `System*`; each third-party package under `// <Package>`; project namespaces (`Vtk`) under `//`; `using static` under `// static usings`; aliases under `// alias directives`.
  - `.slnx` solutions; assembly attributes in the csproj (`<InternalsVisibleTo Include="..." />`); generated code never edited.
- **Tests:** NUnit 4 with `Assert.That` constraints; explicit `// Arrange` / `// Act` / `// Assert`, one behavior per test; grouped asserts in `using (Assert.EnterMultipleScope())`; `Action`, not `TestDelegate`; non-ASCII paths and text through `NonAscii`. net35 runs on CLR 2 through NUnitLite (`Net35.cs`).
- **License headers:** source files (`.cs`, `.i`, `.hxx`, `.cxx`, `.py`) start with `SPDX-FileCopyrightText: 2026 Paul Büchner` and `SPDX-License-Identifier: MIT`, in the file's comment style; none in project, build or config files.

## Gotchas

- **`Finalize`:** `vtkRenderWindow::Finalize()` and nine others clash with C#'s finalizer (CS0465): netvtk-gen leaves them out (logged as a name clash).
- **Per-platform declarations:** netvtk-gen sees Windows' only. `vtkMultiThreaderIDType` (a DWORD, `pthread_t` elsewhere, a pointer on macOS) and `vtkOpenGLRenderWindow::CreateOverrideAttributes` (declared off Apple only) broke the macOS build: excluded in the config. CI's macOS job is the check; the wrapped headers' `#if` blocks on `__APPLE__`, `_WIN32` and the like are the candidates (none else declares a wrapped member, 2026-10-13).
- **Windows-only declarations:** the generator runs on Windows, the output builds everywhere. `windows.h` maps `GetClassName` to `GetClassNameA`/`W`, which VTK declares on Windows only (left out in the config); headers VTK installs on one platform only are a platform module (netvtk-gen's `vtk_module`, `headers`, `platforms`: RenderingOpenGL2Win32 takes `vtkWin32OpenGLRenderWindow.h` and `vtkWin32OpenGLDXRenderWindow.h`, in NetVtkWin32) or `exclude_headers` (the other `vtkWin32*Window*.h`, `vtkTestOpenGLVersion.h`).
- **Direct3D interop** (`vtkWin32OpenGLDXRenderWindow`, needs `WGL_NV_DX_interop`): VTK creates its own device with `D3D11_CREATE_DEVICE_DEBUG`, which fails without Windows' Graphics Tools: give it the application's context (`SetD3DDeviceContext`) before `Initialize`, as the tests do (`Direct3DDevice`). The shared textures have one sample unless `SetSharedTextureSamples` matches the window's (`SetMultiSamples(0)`); OpenGL renders into the shared render framebuffer, and reads it, between `Lock` and `Unlock`. `SetAdapterId` takes the LUID as a long (`extras/RenderingOpenGL2Win32.i`). Several DX windows work in one thread, a deleted one lets go of the Direct3D device, and a hardware selector's capture leaves the shared render framebuffer as it is (the port's patches). Changing the window's samples re-creates the render framebuffer: share its new texture with `RegisterSharedRenderFramebuffer`, after a render. Registering a texture that was attached to a framebuffer before, as `RegisterSharedRenderFramebuffer` does, costs its size for good with NVIDIA's driver (616.92), whatever the order it and the framebuffer go in; one registered before it is ever attached costs nothing. A hidden window narrower than Windows allows (120 pixels here) is widened after VTK made its framebuffers: its renders then differ from one to the next.
- **Heredocs:** in this environment a quoted heredoc loses `\\` (it becomes `\`): Python with backslashes goes into a file first.
- **Platforms:** win-x64 and win-x86 build, test (every framework) and pack (2026-10-11). Linux: `docker/linux-x64.Dockerfile`. macOS: CI's natives job tests without the rendering tests and its package tests pass (2026-10-13); VTK, natives and pack also build on a Mac (osx-arm64, 2026-10-21).
