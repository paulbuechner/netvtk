# netvtk-core

SWIG-generated C# bindings for VTK 9.7.1: one C# namespace, `Vtk`, VTK's class and method names unchanged; one SWIG module per VTK module (`<Module>Module`, internal). Monorepo rules: `../CLAUDE.md`; roadmap: `../PLAN.md`. Forked from `../../netocc/netocc-core` (same author, MIT): its `CLAUDE.md` explains every typemap and rule this folder kept; this file holds what differs and what is VTK's.

The modules in `src/SWIG_files/wrapper` (25 VTK modules), their `headers/`, `modules.json`, `classes.json` and the structs in `src/NetVtk/<Module>/*.g.cs` are written by `../netvtk-generator` (banner `generated by netvtk-gen from VTK <version>`): change the generator or its config, never the files. Hand-written: `src/SWIG_files/common/*.i` (the typemap library), `src/SWIG_files/extras/<Module>.i` (companions), `src/Native/` (NetVtkRuntime), `src/NetVtk/Runtime/`.

## Commands

```bash
python build.py tools                        # once: SWIG 4.5.1 from conda-forge into .tools/ (micromamba)
python build.py vtk --triplet x64-windows    # VTK via vcpkg: about 23 min first time (x64 and x86 alike); cached after
python build.py generate                     # after any .i change
python build.py native --triplet x64-windows # after generate; repeat for x86-windows
python build.py test --arch x64              # every framework, net35 on CLR 2; also --arch x86; --no-rendering without OpenGL 3.2
python build.py pack --rids win-x64,win-x86  # NuGet into artifacts/packages (CI packs all four RIDs)
python build.py test-package --arch x64      # the packed NetVtk as an app consumes it
python test/test_build.py                    # build.py's version, changelog and SWIG message rules
python build.py registry                     # versions/ at the repository root after a committed port change (--check: CI)
# the hand-written C++ against .clang-format, with CI's clang-format (a venv under .tools/)
python -m venv .tools/clang-format && .tools/clang-format/Scripts/python -m pip install clang-format==20.1.8
.tools/clang-format/Scripts/clang-format --dry-run --Werror src/Native/*.cxx src/Native/*.hxx
```

Logs into `log/` (gitignored): `python build.py test --arch x64 > log/test-x64.log 2>&1`. Linux: `docker/linux-x64.Dockerfile` (header comment), with Docker Desktop running.

## VTK (the vcpkg port)

- **`vcpkg/ports/vtk`** builds VTK 9.7.1 from Kitware's GitHub tag with the module set of `../PLAN.md` (`NETVTK_MODULES`, every group `DONT_WANT`; VTK enables what they depend on: 77 libraries). Features add modules: `volume` (RenderingVolume, RenderingVolumeOpenGL2), `exodus` (IOExodus), `cgns` (IOCGNSReader); `vcpkg.json` asks for all of them, and so must netocc-core's manifest: another feature set is another VTK build. Its third-party libraries are VTK's own copies with mangled symbols: the port depends on no other port, and nothing clashes with the zlib or FreeType OCCT links. 64-bit ids on every architecture (`VTK_USE_64BIT_IDS`), `STDThread` SMP, no wrapping, versioned names (`vtkCommonCore-9.7.dll`).
- VTK's two executables go to `tools/vtk`, where the config fixup points its CMake targets. Its licenses (its own, its modules', the third-party ones) go to `share/vtk/licenses/VTK`, from which `build.py native` writes `THIRD-PARTY-NOTICES.txt`.
- The `opengl` feature is empty: OCCT's `vtk` feature asks for `vtk[opengl]`.
- **Triplets** are netocc's, byte for byte (its OCCT block included, which only the opencascade port reads); release-only, macOS deployment target 14.0. vcpkg's ABI hash covers the triplet file: identical files make NetOcc's VTK (opencascade[vtk] from this registry) the same build as NetVtk's, with the same ABI hash, and either binary cache serves the other. Change them in both repositories together.

## Wrapper contract (what differs from netocc's)

- **VTK objects** (`common/VtkObjects.i`): `%vtk_object(T)` before each class deriving from `vtkObjectBase`. The proxy is the object and owns one reference; Dispose and the finalizer drop it (`UnRegister`: SWIG's unref feature, no ref feature).
  - `T::New()` and `NewInstance()` hand over a reference of their own: declared `T*`. Every other returned object gets one from the wrapper: declared `T* const`. A callback's object parameter too.
  - `%vtk_new(T)`: a C# constructor calling `T::New()`; the object factory picks the class (`new vtkRenderWindow()` is the platform's OpenGL window).
  - The finalizer may delete an object on its own thread. Rendering objects release OpenGL resources in their destructors: dispose them on the rendering thread.
- **Size hints:** a pointer VTK returns with `VTK_SIZEHINT(N)` is a C# array of N, copied right after the call: `%apply TYPE *NETVTK_SIZE<N> { TYPE *Member }` before the declaration, `%clear` after (`%netvtk_sized_return`; double and int, N = 2, 3, 4, 6).
- **Width typedefs:** `vtkIdType` and `vtkMTimeType` keep their names in the wrappers (`long long` or `long` per platform): C# `long` and `ulong`. C `unsigned long` (event ids, observer tags) is `ulong`, range-checked on Windows (`Types.i`).
- **Directors** (`common/Directors.i`): `%netvtk_director(T)`, `%netvtk_directed(T)` as netocc's. An exception an override throws does not unwind through VTK: `Directors.Fail` parks it and hands its number to NetVtkRuntime (`NetVtk_DirectorFailed`); the callback returns (an override with a result returns its default) and VTK goes on; the wrapped call that led to it takes the number after its call (`Exceptions.i`) and C# throws a `VtkException` (`NetVtk_ManagedException`) whose InnerException is the C# one. NetVtkRuntime holds it per thread for every wrapper library: the callback's module and the call's differ.
- **Exceptions:** `VtkException` carries a C++ exception's type (`std::bad_alloc`, `std::out_of_range`, ...) and message. VTK reports its own errors through `vtkOutputWindow`, not exceptions.
- **Proxy constructors** `(IntPtr, bool)` are `protected internal`: NetOcc.Vtk's proxies derive from NetVtk's in another assembly. Other code makes proxies with `vtkObjectBase.FromNativePointer<T>(pointer, ownsReference)` (a reference of its own, checked by `T.SafeDownCast`); `NativePointer` is the object's `vtkObjectBase*`.
- **Hand-written members:** every proxy is `partial` (`NetVtk.i`); `src/NetVtk/<Module>/<Class>.cs` adds C#: `vtkObjectBase` (`ToString` from VTK's `Print`, native pointers), `vtkObject` (handlers as observers: `AddObserver(id, handler)`, `Observe`, the events `ModifiedEvent`, `ErrorEvent`, `WarningEvent`), `vtkAlgorithm` (`StartEvent`, `ProgressEvent`, `EndEvent`), `vtkDataArray` (`ToDoubleArray`: a typed loop through `vtkArrayDispatch` for VTK's AOS and SOA arrays, value by value for the others). The typed arrays' bulk members are `cscode` macros in `extras/CommonCore.i` (`ToArray`, `CopyFrom`, `AsSpan` on .NET 6+, `FromArray`), copying with NetVtkRuntime's `NetVtk_CopyMemory`.
- **NetVtk's own director subclasses** (`DelegateCommand`, `VtkOutput`'s output window) carry `[CSharpOverrides]`: `Directors.Overrides` connects no callbacks for the other types of NetVtk's assembly, its proxies, whose overrides are C++'s.
- **Messages:** `VtkOutput.Install()` (or a `Message` handler) makes a C# `vtkOutputWindow` subclass VTK's instance: every message to `Message`, to `Trace` without a handler. The tests install it (`TestSetUp`): VTK's own opens a window on Windows.
- **Finalizer:** `VtkFinalizer.Context` set, the finalizer posts the release there (`csdispose` of `vtkObjectBase` in `VtkObjects.i`).
- **Package:** NetVtk carries the SWIG files it was built from in `swig/` (`common`, `wrapper`, `extras`, `headers`, the JSON indexes) and `swig/interop/NetVtkInterop.i`.
- **Interop for other bindings** (`src/SWIG_files/interop/NetVtkInterop.i`): another SWIG binding (NetOcc.Vtk) `%include`s it, not NetVtk's typemap library, whose typemaps use NetVtk's internals and whose global ones would apply to the binding's own classes. `%netvtk_object(T)` passes NetVtk's objects (`NativePointer` in, `FromNativePointer` out, with NetVtk's reference rules); `%netvtk_derived(T, Base)` makes the binding's VTK class a subclass of NetVtk's proxy (the `protected internal` pointer constructor; the base proxy holds and drops the reference). Change it as public API: NetOcc.Vtk builds on it.
- **Autoinit:** the module whose classes other modules' object factories override registers them when its library loads (`VTK_MODULE_INIT` in the `.i`'s `%{ %}`: RenderingCore registers RenderingOpenGL2, InteractionStyle, RenderingFreeType, RenderingUI; RenderingVolume registers RenderingVolumeOpenGL2).
- **Native libraries:** `NetVtk<Group>` per entry of `src/SWIG_files/modules.json` (Common, Filters, IO, Rendering, Interaction), each linking all of VTK (exports, of 65535: Common 30,542, Rendering 12,248, Filters 10,857, Interaction 7,042, IO 2,162); `NetVtkRuntime` (director failures, memory streams) links nothing and every wrapper library links it.
- Kept from netocc as they are: Types.i, References.i (keep-alive), Strings.i (UTF-8; no OCCT strings), Streams.i, ValueTypes.i, Std.i, `NativeLibraryLoader`, `NativeKeep`, the net35 rules.

## Registry and CI

- **vcpkg registry:** the repository is a vcpkg git registry for the VTK port: `versions/` (repository root) names each port version's git tree. After a change to `vcpkg/ports/vtk`, commit it, raise its `port-version` if its version stays, run `python build.py registry` and commit `versions/`; `build.yml` fails on a stale one (`registry --check`). NetOcc pins the registry at a NetVtk release's commit.
- **Rendering tests** (`[Category("Rendering")]`) need OpenGL 3.2: CI runs them on Linux (Xvfb, Mesa's llvmpipe) and leaves them out on Windows and macOS (`--no-rendering`).

## Rules

As `../../netocc/netocc-core/CLAUDE.md`'s (license headers, C# style, net35 limits, tests), with VTK in place of OCCT. VTK's sources and wrapping tools (BSD-3) may guide rules; ActiViz and other bindings' code never.

## Gotchas

- **`Finalize`:** `vtkRenderWindow::Finalize()` and nine others clash with C#'s finalizer (CS0465): netvtk-gen leaves them out (logged as a name clash).
- **Windows-only declarations:** the generator runs on Windows, the output builds everywhere. `windows.h` maps `GetClassName` to `GetClassNameA`/`W`, which VTK declares on Windows only (left out in the config); headers VTK installs on one platform only (`vtkWin32*Window*.h`, `vtkTestOpenGLVersion.h`) are `exclude_headers`.
- **Heredocs:** in this environment a quoted heredoc loses `\\` (it becomes `\`): Python with backslashes goes into a file first.
- **Platforms:** win-x64 and win-x86 build, test (every framework) and pack (2026-10-11). Linux: `docker/linux-x64.Dockerfile`. macOS: CI only.
